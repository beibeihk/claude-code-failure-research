# Research roadmap and completion boundary

The researcher explicitly declines Claude accounts, login and spending. This
cycle now conducts real local client-engine contracts via `claude plugin test`
and published built-in mod source. See the [no-cost study](no-cost-research.md).
It does not complete the eventual production discovery → report → feedback →
verified-fix chain, nor does it establish model coding performance.

Active no-cost priorities are instruction loading/deduplication, diff rendering
and Git snapshots, hook dispatch and component failure handling. Contracts use
synthetic world responses and can support client/source findings. Existing public
reports supply candidates and duplicate checks, not our own reproduction evidence.
Local scripted API transport and substitute-model backends are possible later
client-only designs; neither has been implemented or executed here.

| Priority | Question | Current deliverable | Remaining evidence |
|---|---|---|---|
| P0 | Instruction/constraint retention | V01 preserved, model execution disabled | Model evidence unavailable under no-spend policy |
| P1 | Long-horizon goal drift | L01 protocol | Real multi-module fixture, observed step strata |
| P2 | Verification and false claims | Immutable invoice fixture and analyzer | Live traces, manual claim labels, repeated trials |
| P3 | Hook reliability | Passive fixture, count/order diagnostics | Stream-correlated live delivery and controls |
| P4 | Permissions/auto | Current precedence and classifier rules audit | Benign refusal tests and classifier availability control |
| P5 | Instruction loading | Official engine and authored contracts executed | Nested Read contracts, supported option variations |
| P6 | Context/compaction | Matched-boundary protocol | Supported compact control and actual boundaries |
| P7 | Subagents | Candidate screening and inheritance guide | Child traces, parent interpretation, conflict verifier |
| P8 | Diff/Git | Official tests and Windows virtual-path controls executed | Actual filesystem/Git-backed client reproduction if a product candidate emerges |
| P9 | Error recovery | Versioned candidate screening | Controlled local tool faults, retry records |
| P10 | MCP | Candidate screening | Synthetic server, transport/auth/schema controls |
| P11 | Remote Control | Availability-sensitive protocol only | Official eligible session and reconnect observations |
| P12 | IDE/CLI | Surface classification criteria | Same-case supported IDE setup and paired runs |
| P13 | Plugin/hook interaction | Plugin-independent fixtures | Optional instrument arm and clean reproduction |

V01 is the only automated model coding runner implemented and is policy-disabled.
The active client runner is `runners.run_client_tests`. H01 has a prepared
fixture and offline observer/analyzer tests. L01 is design-only. This explicit
boundary prevents protocols or software unit tests from becoming claimed studies.

After a selected E3/E4 case exists: fresh duplicate search, 2–5 relevant ablations,
minimal public fixture, root-cause hypothesis with unknowns, independent review,
human readability review, and at most one new issue. A matching existing issue
receives incremental evidence instead of a duplicate. Security cases remain private.

For official responses, keep one versioned status card. Retest a reported fix
against the original fixture and compare actual before/after counts; distinguish
client release from model update. Configure an explicit quiet monitor only once
there is a real issue to monitor.
